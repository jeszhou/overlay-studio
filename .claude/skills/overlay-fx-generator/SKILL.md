# 特效生成:SRT → Overlay JSON

把 SRT 字幕自动编排成动效卡片时间轴,输出 **overlay JSON**,用户在 Overlay Studio(仓库里的 `motion-playground`,双击「启动 Overlay Studio.command」或 `npm run dev`)里点「📥 导入 JSON」即可预览微调。

## 开工与收工(每次会话的固定动作)

- **开工先读 STATUS.md**:在这期视频的素材目录里找 `STATUS.md`(和 SRT/JSON 同目录)。有就先读,按里面的「当前阶段」和「待办」接着干,不要求用户重新交代;没有就从同目录 `STATUS.template.md`(本 skill 目录下)复制一份创建,填上已知信息。
- **卡片库变了就同步 skill**:只要 `motion-playground/src/effects/` 新增或删除了卡片,跑 `cd motion-playground && npm run sync:cards` —— 下方【卡片库】会自动多出/移走对应行,新卡的「触发条件」列留着 `⬜ 待补`,补一句「什么时候用这张卡」即可(用途和参数是从源码读的,不用手写)。不确定有没有漏,跑 `npm run check:cards` 查。
- **开工先读偏好表**:同目录 `我的偏好.default.md`(出厂中性默认)+ `我的偏好.md`(用户自己的,同名条目覆盖默认)。本文档里凡是写成 **【偏好·分区·条目】** 的地方,取值一律去这两份表里查,**不要自己编数字**。两份都查不到就按 default 表的说法办(多数是"不设/可选",那就真的不设)。
- **收工必更新 STATUS.md**:每次交付/修改完,把当前阶段、关键文件路径、本期决定(主色/皮肤/风格)、已完成、待办、运镜建议清单写回去。下一个会话靠它接力。

## 工作流程

1. **解析 SRT**:提取每条字幕的 start/end(秒)和文本。相邻字幕如果属于同一个语义段(同一个观点/列举/数据),合并为一个时间区间。
2. **分段脚本(先于选卡,本 skill 的核心步骤,见【先分段,再配卡】)**:把整篇稿子拆成「章 → 段 → 元素」三级:章 3-6 个(给 `chapter-bar`);**段 = 10-30s 恰好一个论点**,每段标注 起止秒/中文标题/英文小标签/语义色/段界收法;元素 = 段内的数字/截图/图表/结论行,各自标进场秒(对齐台词句)。每个论点标注证据形态(数字?截图可证?取舍?立场?量级对比?)——这决定用哪张证据卡。**是"用动画呈现语义",不是"给字幕加特效"**:卡的内容来自论点和证据,不是 SRT 原句复述。
3. **识别内容类型**:钩子设问 / 痛点罗列 / 反转金句 / 数据 / 术语解释 / 步骤流程 / 引用他人 / 对比 / 列举 / 分点 / 结尾升华……
4. **匹配卡片**:先读同目录 `我的偏好.md` / `我的偏好.default.md`(取值表)和 `经验规则.md`(定性偏好),和本文件规则合并;冲突时以更具体、更新的为准,再按下方【卡片库】的触发条件选卡。**只能用卡片库里的 kind,严禁发明新类型。** 若用户提供了「脚本设计」文档(每段已配好卡),以该文档为准,只补时间和缺漏。
5. **编排落位与密度**(见【编排规则】)。
6. **输出纯 JSON**(见【输出格式】)+ 分段脚本(段落表,方便用户检查段落划分)+ 素材清单(见【素材清单】),除这两者外不输出解释文字。
7. **lint 自检(交付前必跑)**:`cd motion-playground && npm run -s lint:overlay -- <生成的.json> [--duration 视频秒数]`。**error 必须修完再交付**(占位文案残留/时间越界都是硬伤);warn 不强求修,但要把 warn 列表附在交付说明里给用户过目。规则阈值在 `motion-playground/lint-rules.default.json`(公共)+ `lint-rules.local.json`(用户个人,含三档尺寸等)。

## lintOff 是用户的主动决定(硬规则)

卡片上的 `"lintOff": true` 或 `"lintOff": ["规则名"]` 是用户在 Studio 里亲手点「忽略」写下的标记,表示"我知道这条规则,我就是要这样"。**重新编排、单卡重写、加密时一律原样保留这个字段,严禁把这张卡"修复"成规则认可的样子。**

## 输出格式(必须严格遵守)

```json
{
  "version": 1,
  "aspect": "16:9",
  "theme": "dark",
  "cards": [
    {
      "id": "card-1",
      "kind": "blur-text",
      "start": 0.5,
      "end": 4.2,
      "params": { "text": "你是不是|也这样?", "accent": "blue", "position": "center" }
    }
  ]
}
```

- `aspect`:`"16:9"`(1920×1080)或 `"9:16"`(1080×1920)。用户明确说横屏/竖屏时必须写入对应值;没说则默认 `"16:9"`。禁止自定义任意宽高。
- `theme`:`"dark"`(暗调视频)或 `"light"`(亮调视频)。用户没说就问一句;不方便问默认 `"dark"`。
- `id`:`card-1`、`card-2`… 递增,不得重复。
- `kind`:必须是卡片库中的 id。
- `start`/`end`:秒(可带小数),**必须来自 SRT 的真实时间**,end > start。
- `seg`(卡片顶层字段,可选):**段落分组**——同 seg 的卡进入自动顺排容器,间距 28px,左边线天然共线,卡高变化自动让位。横屏从 x=120,y=96 起排;竖屏从安全区 x=72,y=192 起排。首成员(整段最先出现的那张卡)是整段的拖拽把手:它的 offsetX/offsetY 移动整段;其余成员的 offset 是组内微调。**同一段里并排陈列的卡必须同 seg**;一段跨了好几句时,后进场的卡照样并进同一个 seg(会在前面的卡下方自然接替)。独立大卡(type-shift/terminal-3d/focus-card 等一段一张的)不用 seg。
- `params`:只写需要覆盖的字段,其余自动用该卡调试好的默认值(**不要臆造字段**)。
- 通用参数(所有卡都支持):`theme`(覆盖全局)、`offsetX`/`offsetY`(位置微调 px)、`accent`(强调色,只能用这三个:`blue`(数据蓝)/`alert`(否定红)/`orange`(转变橙))、`scale`(单卡大小倍数)、`speed`(单卡动画速度倍数,默认 1)。
- **禁止**:新卡片类型、自定义 UI/样式字段(如 x/y/w/fontSize/color 十六进制)、无时间的卡、把整期内容塞进一张卡、输出 JSON 以外的内容。

## 常驻层(见【偏好·常驻层】)

全程在场的常驻层能让画面不空。**配哪几张、配不配,见【偏好·常驻层】**;要配的话各一张,start=0、end=视频结尾:

1. `chapter-bar` 章节导航条:把稿子分成若干章(章数、章名长度见【偏好·常驻层】),`chapters` 填「章名 起始秒」(| 分隔)。章节切换点选在讲述的自然转折句上。
2. `caption-track` 双语字幕层:`lines` 一行一条 `起始|结束|中文|英文`。中文从 SRT 原句轻度整理(去语气词、口误);**每条都给英文翻译**(短而地道,小字展示);每条至少标一处 `*关键词*`(这句真正的重点词,标了会被强调色点亮)。文本里不许出现竖线(用 / 代替)。


这两类常驻卡都不计入"密度/多样性"指标,也不受"相邻不同 kind"约束;其余内容卡照常编排。

## 先分段,再配卡(段落场景制,优先级最高)

整体感来自"按段组织版面":**逐句进场的是元素,按段组织的是版面**。严禁直接从 SRT 逐句挑卡——必须先做出【工作流程】第 2 步的分段脚本,再按段编排:

1. **分段脚本格式**(每段一行):`起止秒 | 中文标题 | 英文小标签 | 语义色 | 段界收法 | 元素列表(形态+进场秒)`。标题长度见【偏好·文字量】;英文小标签 = 段意的英文直译,**配不配、什么字体风格见【偏好·文字量·英文小标签】**,填进卡的 kicker/en 类字段。
2. **段落要有人立着**:没有专门的段头卡,这件事交给常驻的 `chapter-bar`——一张从 0 拉到片尾,`chapters` 参数按「章节名 起始秒」写全本期段落,讲到哪推进到哪。段落开场想再重一点,可以让 `stat-proof` 的 kicker 或一张 `type-shift` 承担立题,但不必每段都加。
3. **一段一结构(整体感的来源,最重要)**:同段的卡可填 `seg` 字段共线顺排(**用不用见【偏好·结构·seg】**)。没有专门的段头卡,**段落感由常驻的 `chapter-bar` 承担**——顶部章节导航从头到尾在场,讲到哪一段就推进到哪一格,观众永远知道现在在哪。一段的标准结构是**主卡 + 钉板**两件:段内**最多一张"标志性主卡"**承担这段的主要画面(terminal-3d/focus-card/巨字这类,一段一张);零散要点用 `pin-board` 钉在角落陪跑整段,讲过不撤。**数字和数据用专卡而不是堆文字**:一出现数字/比例/趋势,直接上 ring-metric / odometer / stat-proof 这类"动画在演语义"的卡,别用纯文字讲数字。**严禁一段叠四五张各自为政的小卡**(每张卡底板/字号/宽度都不同,offset 对得再齐也是乱的)——整体感来自 chapter-bar 的统一节奏,不来自堆卡。段内只进不出:元素踩台词进场,停到段尾。
4. **段界统一清场**:段落结束时同段所有卡一起退场(共用 end);或整段交给全屏卡(`focus-card`,或用户自己导入的录屏底)换景。**换景频率见【偏好·结构】**,给观众喘息。
5. **一段一色**:段内所有卡 `accent` 一致 = 该段主色(色义约定见【偏好·颜色】)。
6. **来源行是证据的标配**:证据卡必须带出处(`stat-proof` 的 footZh、`pin-board` 的 subtitle、`quote-lockup` 的 author),格式仿 mono 来源行:`SOURCE·OpenAI官方·2026.6` / `NEWS·7/14·一个人手搓` / `CASE·博主自述`。没有出处的截图不算证据。
7. **对照排版按画幅分支**(GLOBAL vs CHINA 式):段意本身是国外vs国内/旧vs新/A派vs B派时,横屏可拆成两个同时间窗的 seg 分组——左组正常,右组的段头填【偏好·落位·双列对照的右列 offsetX】整组挪到人物右侧。竖屏禁止沿用这个横向偏移:优先用 `versus-card` 的上下结构,或把两个信息组按时间先后放进同一安全列;需要人物同屏时使用上下分区。两种画幅都要同段同色,并在交付前检查卡片边界没有越出舞台。
8. **留白段**:密段之间安排"只有段头、什么都不堆"的空段(时长见【偏好·结构】)。不是每段都要厚,呼吸感来自疏密交替。

## 编排规则

- **宁多毋缺(第一原则)**:Studio 里删一张卡只要按一下 Delete,缺一张卡却要重新对时间——所以**拿不准要不要配卡的段落,一律配上**。宁可用户删掉三成,不要让用户补一张。
- **密度**:每分钟张数见【偏好·密度与节奏·密度区间】,跟着语义走——讲到新名词、新数字、新动作、新情绪、新例子就出新东西。目标是**每隔【偏好·密度与节奏·新动作间隔】有一个新动作**(新卡进场,或卡内下一条弹出;两者都算)。留白只给真正的叙述过渡,上限见【偏好·密度与节奏·留白上限】。
- **多样性(硬指标)**:
  - 相邻两张卡**不许同 kind**(常驻章节卡除外);
  - 每 60 秒内要用到的不同分组数、全片 kind 种类数下限、同种卡重复上限,**都见【偏好·多样性】**(偏好表写「不设」就真的不设,别自己补一个)。
- **同屏可以叠 3-4 张,但要"逐条累积"而不是同时炸出**:
  - 每个章节可给一张**常驻章节卡**(如 `step-timeline`/`punch-pill` 放角落,整章不消失,期间其他卡来来去去);
  - 常驻卡之外再叠几张轮换内容卡(上限见【偏好·多样性·同屏叠卡】),落位错开(left/right/bottom/top),进场时间彼此错开的最小间隔见【偏好·多样性·同屏进场错开】;
  - 同一落位同一时刻只许一张可见;**段落结束时同段全体清场(共用 end),再重新开始累积**(见【先分段,再配卡】)。
  - 标注"独占全屏"的卡(focus-card)仍然不与其他卡同屏。
- **落位避人(硬约束)**:人物在画面中间,卡不许盖脸。**有没有固定主轴、哪类内容落哪儿,见【偏好·落位】** —— 偏好表没规定的,按卡片自身建议的 position 落位,别自己发明一套。
- **时长**:各档时长见【偏好·密度与节奏】。内容卡一律跟着讲述时长走,不要套固定值。
- **节奏**:开头 0-5s 必须有一张钩子卡;每个"总结/反转/金句/数字"时刻都配卡。
- **让在场的卡活着(卡内逐条)**:节奏感来自"卡内容在动",不是狂加新卡。超过 8s 的卡一律选能逐条推进的:`pin-board` 逐条钉要点、`checklist` 逐项打勾、`step-timeline` 讲到哪章亮哪章、`focus-card` 要点逐条弹入。别让一张卡一次全亮然后干等。
- **一个论点养一条线索,别撒一把卡**:一个论点占住整段(时长见【偏好·密度与节奏·论点板陪跑】),信息按讲述节奏依次进场——`chapter-bar` 推进到本段立题 → 数据专卡出数字 → `pin-board` 钉住结论要点,钉过的不撤场。厚度感来自累积,不来自卡数。讲人/公司时先钉 `entity-chips` 名牌再展开;讲证据用 `stat-proof` 给数字、`quote-lockup` 给出处。

## 图形优先(重要:防 PPT 化)

动效是**视觉伴奏**,不是把字幕再打一遍。按这个优先级选卡:

1. **证据优先(最高)**:观点要用数字和真素材背书,不要用文字复述——里程碑/成绩用 `stat-proof`(滚动计数);比例/达成度用 `ring-metric`;整数规模用 `odometer`;取舍、二选一用 `versus-card`;要演示的界面让用户「导入视频」把录屏铺成底,再用 `ui-callout` 圈出要讲的那块。
2. **数字可视化**:一出现数字就用 `odometer`/`ring-metric`/`stat-proof`——大数字 + 一行小注,不写整句。
3. **图标/图形结构**:并列列举 → `pin-board`(要点逐条钉住,讲过不撤);流程/步骤 → `step-timeline`(章节大纲)或 `checklist`(逐项打勾);二选一 → `versus-card`;文件/代码/和 AI 的拉扯对话 → `terminal-3d`。
4. **实物图/截图/录屏**:引用他人的话 → `quote-lockup`(逐行揭示 + 署名);演示界面/网页/代码 → 没有专门的录屏运镜卡,让用户在 Studio 里「导入视频」把录屏铺成底,再用 `ui-callout` 圈出要讲的区域;讲界面某个区域 → `ui-callout` 圈出来。聊天记录、群消息这类长文字,让用户录屏或截图铺底,绝不要打成文字卡。
5. **纯文字卡是最后的选择**:只给钩子/反转/金句时刻(`punch-pill`/`blur-text`/`type-shift`/`quote-lockup`),占比上限见【偏好·文字量】。

文字量红线:
- **禁止把 SRT 原句整句搬上卡**(硬约束),必须提炼成词块。**字数上限见【偏好·文字量】** —— 偏好表没给数字,就守住「明显短于口播原句」这条底线。
- 需要长内容时选"图"的形态(截图/封面/引用卡),不选"段落"。
- **卡内节奏必须卡点(重要)**:凡是"逐条/逐步出现"的卡(checklist、step-timeline、pin-board、focus-card、blur-text、type-shift 等),它的节奏参数(`stepMs`/`staggerMs`/`shiftAtMs`/`countMs`)**必须用 SRT 实际时长推算,不许用默认值**:
  - 计算:`节奏参数 ≈ (对应 SRT 段总时长(秒) × 1000) ÷ 条目数`,再按第一条出现所需的进场时间略减 10%。
  - 例:三个痛点分别在 15.1s / 19.1s / 24.6s 开口讲,段落到 27.9s 结束 → 每条约 (27.9−15.1)/3 ≈ 4.3s → `stepMs: 4200`。
  - 条目间隔明显不均匀时,优先把卡拆成时间不同的多张小卡,或选不分条的卡型。
  - `strikeAtMs`(反转时刻)= 转折句在 SRT 里开口的时间 − 卡片 start,换算成毫秒。
- **颜色分工**:同一期里同一语义永远同色,这是硬要求。**但「哪个色代表哪种语义」是设计约定,见【偏好·颜色·色义约定】** —— 偏好表没规定就整期用同一个 accent,千万别每张卡一个色。

## 通用参数(所有卡都支持)

- `dimAt`(秒,时间轴绝对时间):**讲过变浅+缩小**。到点后整卡压暗并缩小(幅度见【偏好·让位与压暗】,偏好表没给就用组件默认值),同 seg 顺排的卡缩放时(zoom 参与布局,下方内容自动上移补位,不会被挤出屏幕),但不退场;整个话题结束才用 `end` 退场。`dimMode` 可选让位方式:`both`(默认,变浅+缩小)/`fade`(只变浅)/`shrink`(只缩小),一般不用填。编排时给每张证据/论点卡都填:值 = 下一个话题开始的秒数。这是"组合感"的关键——旧信息在场但让位,观众随时能回看已讲过的论据。

## 指定卡片(用户点单,优先级最高)

用户可以在给 SRT 的同时**指定某段话用某张卡**,支持三种写法(可混用、可一次点多单):

- **按原话**:「"收藏了不等于学习了"这句用 versus-card」→ 在 SRT 里全文检索这句话(允许近似匹配),用它所在字幕条的真实起止时间。
- **按时间**:「2:10-2:25 用 versus-card」→ 直接用给定区间(换算成秒)。
- **按内容描述**:「讲三个痛点那段用 pin-board」「演示 Obsidian 那段铺录屏底 + `ui-callout` 圈注」→ 先在 SRT 里定位该语义段,再套卡。

处理规则:
1. **点单必须服从**:指定的段落用指定的 kind,即使【图形优先】会选别的卡;其余没点单的段落照常自动编排。
2. 内容仍要按该卡的形态**重新提炼**(词块/条目/节奏参数照【卡内节奏必须卡点】用 SRT 推算),不是把原话搬上去。
3. 点单的卡与自动编排的卡冲突时(同屏同落位/与独占全屏卡重叠),**挪自动卡,不动点单卡**。
4. 指定的 kind 不在卡片库里时,不要硬造:回复一句说明,并推荐 1-2 个最接近的卡让用户选。
5. 找不到指定的那句话/那个时间段时,先问,不要猜。

## 加密(只增不改)

当用户给出**已调好的 overlay JSON + SRT** 并要求「加密/再丰盛一点/多出些卡」时:

1. **已有的卡一张不动**(id/时间/参数原样保留)——那是用户手调过的。
2. 只在**空隙和薄弱段**插入新卡:先扫出 >3s 没有新动作的时间段,按【编排规则】的密度和多样性往里补。
3. 新卡 id 从现有最大编号继续递增,不与旧卡同落位同时刻,不紧邻同 kind。
4. 输出整份 JSON(旧卡 + 新卡,按 start 排序),并附一句:新增了几张、集中在哪些时间段。

## 单卡重写(换卡)

当用户给出**已有的 overlay JSON** 并要求「把 card-X 换成 <kind>」时:

1. 只动那一张卡:`id`、`start`、`end` 原样保留;`theme`/`accent`/`offsetX`/`offsetY`/`scale`/`speed` 尽量沿用。
2. **内容必须重写,不是搬字**:回到 SRT 里该卡时间段(start–end)的原话,按新 kind 的形态重新组织(条目数、格式、节奏参数都按新卡该有的样子来,节奏仍按【卡内节奏必须卡点】规则用 SRT 推算)。
3. 其他卡一律不动,输出**整份 JSON**。
4. 没给 SRT 时先要 SRT;实在没有,就基于旧卡文字改写,但要说明是降级处理。

## 学一下(从用户的修改沉淀个人偏好)

**不自动跑**。用户在 Studio 导出后说「学一下」才执行。
**这是用户长出自己风格的唯一通道** —— 出厂的 `我的偏好.default.md` 是中性的,
不跑这一步,他每期都在用别人的取值。用户第一次导出时 Studio 会提示他这件事,
但如果他问起「怎么让它更像我的风格」,答案就是这一节。

执行步骤:

1. **拿素材**:读 `motion-playground/exports/review-logs/` 里**最新**的 `*-review-log.json`——Studio 每次导出 JSON/MOV 时自动落盘,含 `origin`(AI 初选编排)和 `final`(用户调完的终选)。用户也可以直接丢两份 JSON。
2. **逐卡 diff**,归类:被删的卡 / 新增的卡 / 换了 kind 的卡 / 挪了时间的卡 / 改了参数的卡(位置/大小/节奏/文字/颜色)。
3. **抽象可泛化的偏好**,不记流水账:同类修改出现 ≥2 次才算倾向;只出现一次的,先问是不是巧合。对比"AI 为何这么编 vs用户为何这么改"。
4. **逐条确认**:这是**正当例外**(这期特殊,不学)还是**改规则**(以后都这样)?只写"已确认"的。
5. 确认的结论**按性质分两个文件写**,每条都带出处 `(学于 <视频名> YYYY-MM-DD;已确认)`:
   - **能填进取值表的**(密度几张/分钟、字数上限、落位主轴、色义映射、时长档、开关要不要开……)
     → 写进同目录 **`我的偏好.md`**,对应 `我的偏好.default.md` 里的同名条目。
     没有 `我的偏好.md` 就照 default 表的分区结构新建一份。**不要改 `我的偏好.default.md`**(升级会覆盖)。
   - **只能用一句话说清的定性规则**(哪类卡降权、什么情况下换什么打法、他为什么这么改)
     → 写进同目录 **`经验规则.md`**。
   与既有条目冲突时,提醒用户二选一,别两条都留着。
   机器可判的阈值(驻留秒数、scale 档位、空白间隔、底板叠层、块级标题落位)顺手同步一份到
   `motion-playground/lint-rules.local.json`,这样 lint 也跟着他的标准查。
6. 写完提醒:如果你在多个 Agent 里都装了这个 skill,记得同步过去。

## 素材清单(交付时必附)

凡编排里用了带素材位的卡(`focus-card` 的 camSrc),或整段要铺录屏底的地方,交付 JSON 时**必须附一份素材清单**:每张卡一行,写「卡 id · 时间 · 需要用户补什么录屏/截图(具体到'B站后台涨粉曲线'这种程度)」。没有素材清单的编排,这些卡会空着上片。

## 交付方式

生成后把 JSON 存为 `<视频名>-overlay.json` 交给用户,并提示:「在 Overlay Studio 点 📥 导入 JSON 预览,点卡片可微调参数,改完 📤 导出保存」。
