# 竖屏视频工作流

状态：已确认（2026-09-06）

目标分支：`feature/portrait-video-support`

## 目标

1. 让 Overlay 工程可显式选择 `16:9`（1920×1080）或 `9:16`（1080×1920）。
2. 让编辑台预览、项目 JSON 和透明视频导出始终使用同一画幅。
3. 让原有卡片在竖屏安全区内使用单列或上下构图，并保持横屏旧工程兼容。

## 数据契约

- `OverlayDoc` 新增可选字段 `aspect?: "16:9" | "9:16"`。
- 旧工程没有 `aspect` 时继续按 `16:9` 打开，避免改变既有项目和导出结果。
- 解析器只接受上述两个值；非法值返回可读错误，`/api/export` 会在写临时任务或启动子进程前拒绝它，导出脚本也只从同一白名单选择尺寸。
- 项目仍保持 `version: 1`，因为新增字段可选且旧客户端会忽略它，不改变既有字段语义。

## 运行时链路

- `stage.ts` 是前端唯一画幅尺寸来源，并提供 `stageForAspect()`。
- `Canvas` 按工程画幅缩放舞台、设置 `--stage-w` / `--stage-h`、更新拖拽吸附与人物落位；横屏吸附基准为 `120/96`，竖屏为安全区的 `72/120`。
- `ExportView` 使用文档画幅渲染相同尺寸的透明舞台。
- `export-frames.mjs` 在启动浏览器前从白名单解析画幅，并将 viewport 与截图尺寸设为对应分辨率。
- 编辑台全局区提供 `16:9` / `9:16` 分段控件，修改结果进入撤销历史并随 JSON 保存。

## 竖屏布局

- 竖屏安全区采用左右 72px、顶部 120px、底部 180px；人物占位居中靠下。
- `chapter-bar` 从 y=120 开始，顶部锚点与段落栈从 y=192 开始，避免章节条占用平台顶部保留区或遮住正文。
- 通用锚点在竖屏下收窄边距，内容最大宽度不得越出 1080px 舞台。
- 原有术语卡、引用卡、对比卡、步骤卡、金句卡、章节条、字幕层和人物运镜优先验证。
- 横屏专用人物运镜在竖屏下改为上下构图；预览与导出必须使用同一几何。

## 时间轴约束

- `start` / `end` 必须来自用户真实视频的 SRT 或已确认时间码，不根据文稿臆造。
- Overlay Skill 输出时必须显式写入画幅；已有 SRT 时间语义不变。
- 生成或导入 Overlay JSON 后继续运行默认 lint 规则。

## 验收标准

- 缺省画幅、显式横屏和显式竖屏项目均能解析；非法值被拒绝。
- 预览 DOM 在横屏时为 1920×1080、竖屏时为 1080×1920，CSS 变量和 `data-aspect` 同步。
- 导出页及 Puppeteer viewport 与文档画幅一致，不接受任意自定义宽高。
- 切换画幅后可撤销，可导出 JSON，再次导入不丢失。
- 横屏旧工程视觉与导出尺寸不变。
- 单元测试、类型检查、构建、lint 和浏览器桌面视口验证通过。

## 非目标

- 不改变现有时间轴与 SRT 的时间码语义。
- 不在本轮把所有历史横屏卡片重做为专门的竖屏版本。
- 不改许可、版权信息、产品名称或现有远程仓库归属。
